# LABJUDGE-EXT09 三草案判定

## 案①：CIRC重做立项（主线B见证证书化内嵌A，C仅探针，AC1–AC5）

**路线选择稳健性：较高。**
把 B（见证/证书化）设为主线、A 内嵌为被见证对象、C 降格为探针，本质是把“可信度来源”从自证转为第三方可验背书，符合可审计系统的一般演进方向。AC1–AC5 若覆盖“证书生成→存储→引用→失效→争议”全链，路线是收敛的。

**机器复核：可行但需补一条。**
AC1–AC5 通常是可判定谓词（存在性、一致性、可重放性）。风险在于 AC 中若含“见证充分性”这类语义判断，机器只能验“证书存在且签名有效”，不能验“见证内容真实”。建议明确：AC 只对**证书结构与引用完整性**负责，内容真实性交由下游争议层。

**制度漏洞：C 仅探针的边界未锁死。**
若 C 的探针输出可被回灌进主线证据链，则“探针”名存实亡，会污染 B 的证书独立性。需硬性条款：**C 输出不得作为 A/B 证书的生成输入**，仅可用于告警与度量。

**票：pass（附条件）。**

## 案②：缓存锚域限条款（fallthrough DONE 四条件 + BLOCKED 四触发 + 缓存锚≠内容认证）

**路线选择稳健性：中。**
“缓存锚≠内容认证”是本案最有价值的一条，直接堵住“缓存命中即视为内容可信”的经典漏洞。但 DONE/BLOCKED 的边界设计是本案最脆弱处。

**机器复核：DONE 侧可复核，BLOCKED 侧弱。**
- DONE 四条件若均为可观测谓词（如：fallthrough 已发生、锚域匹配、签名有效、无未决 DISPUTED），可机器判定。
- BLOCKED 四触发若含“疑似投毒”“锚域可疑”这类启发式，则只能人判或阈值判，机器复核只能验“触发标志是否被置位”，不能验“置位是否正确”。

**制度漏洞（重点）：**
1. **DONE/BLOCKED 非互斥风险**：若四条件与四触发可同时成立，系统必须规定优先级。建议硬性：**BLOCKED 优先于 DONE**，且 DONE 判定前必须显式排除全部 BLOCKED 触发。
2. **fallthrough 的静默失败**：fallthrough 若“未发生”与“发生但未记录”不可区分，DONE 条件会被误判为满足。需强制 fallthrough 的**存在性证明**（事件日志+序号），否则 DONE 不可达。
3. **缓存锚域限的递归漏洞**：若锚本身可被缓存，则“锚域限”可被绕过的套娃。需条款：**锚不可被自身缓存结果所锚定**（反自指）。
4. **BLOCKED 无超时**：四触发若只进不出，系统会永久 BLOCKED。需补 **BLOCKED→重验→DONE/拒绝** 的退出路径。

**票：fail（就当前边界设计而言，需修正后重提）。**
理由：DONE/BLOCKED 互斥性、fallthrough 存在性证明、锚反自指三项缺失，属制度级漏洞，非实现细节。

## 案③：A1 堆叠升级（L0 确权锁边界，L1/L2 契约 JSON 化，DISPUTED 停层）

**路线选择稳健性：较高。**
L0 确权锁边界 + L1/L2 契约 JSON 化 + DISPUTED 停层，是“分层+契约+争议冻结”的标准稳健组合。JSON 化使 L1/L2 可机器校验，方向正确。

**机器复核：L1/L2 强，L0 弱，DISPUTED 中。**
- L1/L2 JSON 契约：schema 可验，强。
- L0 确权锁边界：若“确权”依赖外部权威，机器只能验“锁标志”，不能验“确权正当”。
- DISPUTED 停层：可机器验“是否停”，不能验“停得对不对”。

**制度漏洞（层级停让规则）：**
1. **停层传播方向未定义**：DISPUTED 发生在 L1 时，L2 是否停？L0 是否停？需明确 **停层向上不传播、向下强制传播**（下层不可越过争议层继续消费）。
2. **停让死锁**：若 L1 与 L2 互相 DISPUTED，需有**仲裁层或超时降级**，否则永久停层。
3. **L0 锁边界与 DISPUTED 冲突**：L0 已确权锁定时若发生 DISPUTED，是“锁优先”还是“争议优先”？需条款：**确权锁不豁免争议，但争议不自动解锁**（两者正交）。
4. **JSON 契约版本漂移**：L1/L2 契约升级时，旧 DISPUTED 记录的 schema 兼容性未定义，可能导致停层记录不可解析。

**票：pass（附条件，需补停层传播与死锁条款）。**
